### 时间差（都是 0.1 秒）

1. **UTIL-G1、UTIL-G3 早了 0.1 秒。** 扔出时刻统一取 weapon_fire 的 tick，也就是规则说的“扔出那一刻”。原型 GOOD-08 / DJ-05 用的是 timeline `user_util.throw_tick`，它是道具实体出现的 tick，比 weapon_fire 晚约 7 tick。UTIL-G2 和 UTIL-05 的原型本来就用 weapon_fire，所以没有差。
2. **UTIL-01 的 6-34.8 → 34.7、10-52.8 → 52.7。** 这一波交火从“自己看见敌人”的第一帧算起。common 的 spotted 用 `ticks.pkl`，每 tick 一帧；原型用 daoju 缓存，每 8 tick 一帧。逐帧看：R6 34.656 秒、R10 52.703 秒已经 spotted。

## 约定和取舍（给合并层 / 写复盘用）

- **kind 映射**：问题 → `问题`，好的操作 → `好`，责任判定 → `判定`。规则 blame 写“另一种思路（不算错）”的（UTIL-05/06/07、UTIL-01 的 C 分支）用 `思路` / `—`。UTIL-01 我方 eco 用 `思路` / `合理代价`。UTIL-G1 起晚用 `问题` / `小问题`。
- **blame 取值**：只用 CONTRACT 列的值。UTIL-01 人数差 2 个以上记 `小问题`，并写 `facts.death_cost=true`（死本身合理代价）。
- **merge_key（M5）**：每颗用户道具的 key 是 `util:<回合>:<扔出 tick>`，队友的闪是 `util:<回合>:e<entityid>`。几条命中共用道具时并成一组，组里都取最早那颗的 key（例如 G2 7-18.5 和 G3 7-17.1 都是 `util:7:44514`）。UTIL-01/04/06/07 是 None。
- **句子**：
  - text / alt 末尾不加句号，方便合并层拼从句。
  - 中文和英文、数字之间自动补空格（“第 41.9 秒 2v3 时”“往 A 二楼”“白了 队友C”），人名整体保护，不在名字中间加空格。
- **UTIL-G2 的 alt**：rules_v1 原文“后面对枪对的就是残血”含 validate 禁词“残血”，改成“后面对枪时对面已经掉了血”。
- **UTIL-G2 的证据**：不写伤害数字，只写“一截 / 一大截”，因为对手掉了多少血玩家不一定知道（P1）。UTIL-04 的证据写“打掉你 21 血”，那是自己掉的血。
- **subject**：UTIL-03 只算队友、UTIL-04 时，subject 是扔道具的队友，is_user=false；其余是用户。

## 自己实现的私有 helper（common 里没有）

- `_nades_at` / `_inv_index`：背包里的道具（daoju 缓存的 inventory + weapon_fire 扣延迟）。
- `_spot_ticks`：一段时间里“自己看见任一活敌人”的每一帧（common 只有 `spots()` 返回第一帧），直接读 common 的 spotted 位掩码，只读。
- `_path3`：3D 路程。UTIL-01 B 分支按 rules_v1 用 3D，`common.path_len` 是平面路程。
- `_ev`：道具起爆事件（flashbang/smokegrenade_detonate 带投掷者阵营、entityid）和 player_blind，取 daoju 缓存的 ev。
