# 写复盘（merge / compose / summary / validate）说明

hits.json（规则命中）+ timeline.json + economy.json + shooting.json → `work/<id>/review.json` → 检查文字。
全部是固定表和模板，不调用 AI；同一份输入两次输出字节一样（已测）。

| 文件 | 做什么 | pipeline |
|---|---|---|
| `merge.py` | M1–M7：一回合的 hit → 定稿 moments、主要原因、你的部分、补充从句、ideas | 被 compose 调 |
| `compose.py` | 每回合字段 + 调 summary，写 review.json | `compose` 阶段 `run(ctx)` |
| `summary.py` | headline、走势、可以改进的地方、强项；SUM-01/02/03 在这里实现 | 被 compose 调 |
| `validate.py` | 检查 review.json 每一句；`text_issues()` 也给 M7 用 | `validate` 阶段 `run(ctx)`，返回问题列表 |

调试：`compose.build_review(ctx, hits)` 只返回 dict 不写文件；`py -I engine/validate.py <review.json> [--work 目录] [--hits hits.json]`。

## 规则模块要遵守的 hit 约定（compose 依赖这些）

- `scope`：`moment` 进时刻；`round` 进回合层面（主要原因、经济栏、ideas）；`match` 进总结。带回合号的 `match`（ECO-06/07/08）也给那一回合的经济栏和标题用。
- 和用户阵亡有关的 hit 必须带 `death_t`、`death_of`=用户名（M1 只认这两个字段，不按时间猜）。
- `facts.display`：`summary`（只计入 SUM-01/02）、`merged`（已合进别的句子）这两种不进时刻；`facts.summary_only` 同义。
- `facts.clause`：本条作补充从句时的半句（没有就用整句 `text`）。
- POST-01 的豁免 / 合理代价分支：`blame` 写合理代价，或 `facts.branch` ∈ 豁免/合理代价/保枪，就只当背景。
- TEAM-01 `facts.credit` ∈ 你 / 你和队友 / 关键一枪 / 队友，`facts.mate`，关键一枪 `facts.key_t`。
- TEAM-02 `facts.why` ∈ gift / eco / streak / deficit / clutch / close，残局加 `facts.user_died_before`。
- ECO-09 `facts.slot` = `summary.headline` 或 `summary.momentum`；ECO-07 `facts.buy`；ECO-08 `facts.score_before`。
- TIME-09 `facts.rounds`。TEAM-G1 `facts.variant`（补枪 / 跟上去 / 他找过来）。好操作带经济标签时 `facts.econ_tag`。
- `alt` 必须是填好的句子：还带 `{…}` 占位符的 alt 整条丢掉，并记一条 M7 提示；括号里的知识库编号、规则编号、“对标…”会被去掉（M6）。
- `rule` 必须是 rules_v1 里的编号（validate 第 6 项）。

## merge.py：M1–M7

| 层 | 实现 |
|---|---|
| M1 | 用户阵亡按 `death_t` 分组（相差 ≤0.3 秒算同一次）。主因顺序：POST-01（问题分支）> POST-02 > POST-03 > TIME-06 > UTIL-03 > TIME-07 > TIME-08 > TIME-05 > POS-01 > POS-08 > COST-01 > POS-05 > POS-04 > POS-02 > SHOT-01/02/05（同档按编号）> POST-04 > TIME-03 > TEAM-04。POST-01 背景分支不当主因。TEAM-04 不是主因时只写“比附近的队友先露头”。其余问题写成从句（`；` 接在主句后），“思路”类只进 ideas。这一时刻 kind=关键。 |
| M2 | 阵亡主因是合理代价时，挂在这次阵亡上的 SHOT-01..05 单独成一个“问题”时刻（责任用开枪规则自己的），句尾加“，这次死本身算合理代价”；否则作从句。 |
| M3 | 好操作按同一次击杀分组：同 merge_key、同一个目标 3 秒内、或 0.6 秒内且目标不冲突。主句：TEAM-G1 > SHOT-G4 > SHOT-G3 > SHOT-G2 = SHOT-G1 > TEAM-G2 > UTIL-G2 > 其他。 |
| M4 | 好操作和你的问题同一时刻（1 秒内或同一个目标 3 秒内）：问题是“你的责任” → 好操作不单独成时刻，也不贴进问题时刻的 evidence（夸奖贴在问题旁边读着矛盾，故事线里已经有这次击杀）；问题是“小问题” → 写进好操作这个时刻（what 加从句、better 加问题的还可以），问题不单独成时刻；问题是阵亡时刻的小问题 → 两边各自成时刻；但和好操作是同一次击杀（同一个 tick）时只留问题这一句（同一枪一夸一批并排读着矛盾，d5a R21）。好操作时刻里并进来的小问题，它的“还可以”放 `also`，不放 `better`。 |
| M5 | 同一回合同一个 merge_key 只留一个时刻：阵亡时刻优先 → 规则原文写了“并进这里”的（TEAM-03 收 POS-02）→ 规则编号靠前。另外同一 tick 的开枪类问题（同一串）并成一句。 |
| M6 | better / ideas 只用规则 alt；去掉知识库编号、规则编号、“对标…”括注；“不配…”和没填完的模板丢掉。问题时刻主句没有 alt 时用第一条从句的 alt；团队责任没有 alt 时写固定句“这一条记在队友或团队，你这边没有要改的”；好操作没有 alt 时用规则 plain 作“为什么好”。 |
| M7 | 定稿的 what / better / evidence / 主要原因 / 你的部分逐句过 `validate.text_issues`，记在 issues 里由 compose 打印；真正拦截在 validate 阶段。 |

时刻上限 6 个：关键 > 你的责任的问题 > 好操作 > 其他，留下的按时间排。被挤掉的命中仍算进标签和总结。

### moment 字段映射

| review 字段 | 来源 |
|---|---|
| `t` / `tick` | 主句 hit 的秒（common 取整，整数写 int）/ tick（没有时用回合开始 tick + 秒×64） |
| `kind` | 阵亡时刻、主要原因对应的时刻、TEAM-01 关键一枪 → 关键；好操作 → 好；其余 → 问题 |
| `what` | 主句 `text` + 从句 + 小问题附注 |
| `better` | 问题时刻：主句 `alt`（去掉开头的“还可以”，页面自己加“还可以：”）。好操作时刻（页面标“为什么好：”）：只放夸奖的理由——规则 facts.why_good（ECO-G1：用捡来的枪打出击杀才有，否则为空）、或不是纯建议的 alt（“继续……”“还可以继续……”）、或规则 plain |
| `also` | 只在好操作时刻有：纯建议的主句 alt（“还可以……”）和 M4 并进来的小问题的 alt，页面单独一行标“还可以：” |
| `evidence` | 只写主句 hit 的 `evidence` |
| `blame` | 照 hit 判的写：你的责任；你的责任 + 队友或团队；小问题（含“你的责任（小问题…）”）；队友或团队；合理代价（含“合理代价 + 小问题”）；好操作和另一种思路 → —。页面每种各有一个小标签；“你的部分不能写打得好”、标签排前面按前三种（`merge.YOUR_BLAMES`）算 |
| `rule` | 主句 hit 的 rule |

## 主要原因 / 你的部分

主要原因（main_cause）：

| 回合 | 取法 | who |
|---|---|---|
| 赢 | TEAM-01 | 你（含关键一枪）→ 你；你和队友 → 团队；队友 → 队友 |
| 输 | TEAM-07（送枪）> TEAM-03（TEAM-02 说是连杀、或只能写“人数没拉开”时）> ECO-05（TEAM-02 判装备差距时）> TEAM-02 > ECO-05 | TEAM-07：你或队友；TEAM-03：团队；ECO-05：经济/装备差距；TEAM-02 见下 |
| 都没有 | “这回合赢下/输掉（结束方式）” | 团队 |

TEAM-02 → who：你的责任 + 队友或团队 → 团队；你的责任 → 你；合理代价 → 经济/装备差距；deficit / gift / clutch → 队友；close：你残局前已死 → 队友，否则团队；其他 → 团队。

你的部分（your_part.level），第一条成立的为准：

1. 主要问题：输了，你的阵亡主因是“你的责任”，并且 TEAM-02 把人数先丢算到你（或主要原因是你）。
2. 打得好：赢了，TEAM-01 功劳是你（含关键一枪），并且页面上没有你的责任的时刻；有的话是小问题（先写好的一面，再“不过……”）。
3. 小问题：有任何判到你的问题（你的责任、小问题、合理代价 + 小问题）。
4. 打得好：只有好操作，没有任何关于你的问题时刻（合理代价也算有）。
5. 没问题。

text：先写决定等级的那一面（打得好先写好操作），最多三句；都没有时写“你的阵亡算合理代价”或“这回合你这边没有要改的”。

阵亡时刻的从句：结尾的“被打死 / 倒了 / 这次算合理代价”去掉（这次死只在主句写一次）；连杀（TEAM-03）里有你的，从句只写“X 这一波连杀了 N 个”；POST-03 主句下不再并 POS-05（同一次死换个说法）。

rating（页面在有 your_part 时其实不用它）：主要问题 → 有问题；打得好，或赢了且主要原因是你（你的部分不是小问题）→ 打得好；输了且主要原因是装备差距或主因 hit 是合理代价 → 合理代价；其余 → 正常。

## 联调后的改动（integrate）

合并层（merge.py）：
- 从句排版：和主句相差 ≤1 秒的从句去掉开头“第 N 秒”；开头写的就是主句那一秒也去掉；隔得远的从句用整句（带地点、对象），没写时间的补上“第 N 秒”。TEAM-04 固定半句不加时间。
- 主句已经说过的从句不重复（`_covered`）：TEAM-G1 主句下的 SHOT-G4（人数变化已写过）；TIME-05 已写“第一枪还没停稳”时的 SHOT-01；TIME-06 已写被谁闪白时，同一颗闪的 UTIL-03 只留“之前已经被他闪过一次 / 你站在他前面”。
- 主要原因那条 hit（main_cause 已经写了）不再并进时刻；一个时刻最多 4 条从句。
- M4 写在好操作时刻里的小问题前面加“不过”。
- M1 没有排序表里的规则时，先取你自己的问题，团队级的（TEAM-03 等）留给主要原因。
- 好操作没配 alt 时用规则 plain 做“为什么好”，去掉里面的口径括注（“3 秒内算补枪……”）。
- 你的部分是“打得好”但没有单独的好时刻时，用 TEAM-01 的句子。
- sp() 把以 - 结尾的名字（队友C（第2场））也当英文词。

compose.py：
- POS-06 弱守分支（decisions #23，facts.branch='弱守'，规则 id 仍是 POS-06）标题写“一个人守包点”；POS-01 站位分支（branch='spot'，decisions #10）写“打人时站的位置两个人都打得到”，标签跟着换。
- 标签里带判语的规则名换中性说法：ECO-02“这回合也能强起”、ECO-03“强起输后的买法”、POST-01“人数劣势没保枪”。
