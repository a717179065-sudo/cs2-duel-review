# 规则目录

> 注：rules_v1 写于原型阶段，当时设想由 AI 把事实连成句子；引擎实现后改为固定模板拼句，不调用任何 AI（见 [`engine/compose.py`](../engine/compose.py)）。

由 [`rules/rules_v1.json`](../rules/rules_v1.json) 和 [`engine/config.py`](../engine/config.py) 里的 `EXTRA_RULES` 生成。
规则手册 v1 一共 68 条（`n_rules`），后来按审核单加了 1 条 `SHOT-06`（对枪动作判定），引擎和 validate 都把它当作 v1 的一部分，所以现在一共 69 个规则编号。

- "说明"一栏是 rules_v1 里给人看的通俗说法（`plain`）。每条规则完整的触发条件、责任、固定句式、"还可以"、在第 3 场的期望命中和局限，见 [`rules/rules_v1.md`](../rules/rules_v1.md)。
- rules_v1 之后的改动不回写进 rules_v1（它是只读的测试基准），而是按优先级覆盖：[`rules/decisions_v1.md`](../rules/decisions_v1.md)（用户拍板）> [`engine/knowledge/handbook_v1.md`](../engine/knowledge/handbook_v1.md)（基本功手册）> rules_v1。例如 TIME-04 现在看"第一个人进包点的时间"而不是首杀时间（手册 T-A），SUM-03 去掉了"人数劣势下的击杀"这一类强项（拍板 #27）。实际判法以 `engine/rules/*.py` 和 `engine/thresholds/*.json` 为准。
- 编号里带 G 的是"好的操作"。`kind` 的取值：问题 / 好的操作 / 责任判定 / 合理代价判定 / 经济。

## 开枪与准星

| 编号 | 名称 | 类型 | 说明 |
|---|---|---|---|
| `SHOT-01` | 第一枪没停稳就开 | 问题 | 交火的第一枪，人还在走（没急停）就开了、没打中，而且这次交火有后果（打死人、被打死或挨了枪）。 |
| `SHOT-02` | 准星没放到位 | 问题 | 对方出现时准星离他还差一大截要拉过去，或者准星对着人但比头低、偏在身侧，结果没打赢这一枪。 |
| `SHOT-03` | 一串打空不调整 | 问题 | 对同一个人连开好几枪一枪都没中，中间没有停下来重新对准。 |
| `SHOT-04` | 狙空枪 | 问题 | AWP 或鸟狙在一段时间里连空好几枪，或者空枪有明确原因（没开镜、人还在走、甩横着跑的人、太远、开镜了准星差一大截）。 |
| `SHOT-05` | 拉出去还在走被先打中 | 问题 | 拉出去打一个站着架枪的人，拉出去时人还没停住，被他先打中。 |
| `SHOT-06` | 对枪动作（审核单新增） | 问题 / 判定 | 你的每一次被枪打死都按对枪动作给一个结论：动作对、枪没中就是枪法；动作有错写错在哪一步（审核单第 2 条，手册 1.13） |
| `SHOT-G1` | 停稳先手拿下 | 好的操作 | 步枪、手枪或冲锋枪交火时先停稳再开枪，先打中或者被先打中也没乱动，最后把人打死。 |
| `SHOT-G2` | AWP 停稳开镜先手 | 好的操作 | AWP 或鸟狙停稳开镜再开枪，先手打死对方（包括第一枪空了没走开、第二枪补上，和先挨枪后一枪反杀）。 |
| `SHOT-G3` | 打没看你的人 | 好的操作 | 你看得见对方、对方背对或侧对着你（或者手里拿着道具、刀），你先开枪拿下，没跟他正面对枪。 |
| `SHOT-G4` | 人数劣势里拿下击杀 | 好的操作 | 我方人比对面少（或者只剩你一个）时，你拿下击杀把人数扳回来。 |

## 判断原则（P1–P6）

- P1 只用玩家当时能知道的信息下判断：自己视野、雷达（队友看见的）、击杀栏、自己打中过谁、能听到的枪声和道具声；对方血量、藏身位置、对方经济只能用来写后果或做赛后推算，不能用来说“你当时该知道”。
- P2 能不能看见、能不能补枪，一律用 3D 位置加 demo 的 spotted 可见性，不能只用平面距离。
- P3 不分析语音、报点、聊天，只用 demo。
- P4 经济：手枪局输了一般强起搏一把；反 eco 被翻、下回合全起不了一般强起；强起输了下回合 eco；和强者常见做法不同只当“另一种思路”。
- P5 不是每次死都是错：eco 赌点、人数劣势、装备差距是合理代价；对面 eco 时单独找人头被翻是大问题。
- P6 玩家看到的句子用中文报点和通俗说法，不出现坐标、速度数字、角度、百分比；对标比例只放在 bench，不进句子。

## 责任等级

每条命中都带一个责任等级（rules_v1 `blame_levels`）：你的责任、你的责任（小问题）、你的责任 + 队友或团队、队友或团队、合理代价、另一种思路（不算错）、—（好的操作，不定责）。
合并层决定这回合的主要原因时，同一次阵亡只定一次责（M1），开枪类问题照记（M2）。

## 共用口径（C-*）

所有规则共用同一套口径，实现只有一份，在 [`engine/common.py`](../engine/common.py)，阈值在 [`engine/thresholds/common.json`](../engine/thresholds/common.json)：

| 口径 | 摘要 |
|---|---|
| C-TIME 时刻 | 秒数从冻结结束算，买枪阶段为负数。 |
| C-PLACE 报点 | last_place_name 统一换成中文：TopofMid=中远，Connector=拱门，SnipersNest=VIP，Apartments=B 二楼，Palace=A 二楼，TRamp=A1，Jungle=Jungle，Shop=超市（不再写“B 商店”），Underpass=下水道，Truck=小推车，CT…… |
| C-ALIVE 人数 | 一律按击杀栏（player_death 事件）数，不用每帧 is_alive（采样有滞后）。 |
| C-STILL 停稳 | 开枪那一刻（weapon_fire 的 velocity_X/Y）水平速度 ≤ 这把枪最大速度 × 0.34（AK 约 73，M4 约 76，沙鹰约 78，USP 约 82；开镜的狙按开镜最大速度算，约 34）；超过 180 叫“跑着”，其余超过上限的叫“还没停稳”。 |
| C-HIT 命中 | 开枪后 3 tick 内有这名用户打这个人的 player_hurt。 |
| C-TARGET 目标归属 | 没打中的枪，开枪方向离对方身体不超过 max(5°, 3 个半身宽) 才算在打他；同一串 1 秒内的后续枪按 20° 接上，狙按 8°。 |
| C-SEEN 看得见 | 满足任一条：a 对方 approximate_spotted_by 里有用户；b 这一枪打中了他；c 他 ±1 秒内打中过用户；d 他 ±1 秒内朝用户开过枪，开枪方向离用户身体不到 max(1.5°, 2 个半身宽)，并且我方活人里用户离他的枪线最近，或者用户这时在他的 spotted 里；e 用户 ±1 秒内在他的…… |
| C-RADAR 雷达 | 我方任一活人出现在某敌人的 approximate_spotted_by 里，就算这个敌人上了我方雷达。 |
| C-SMOKE 隔烟 | 3D 视线线段穿过一颗生效中的烟柱（半径约 144、高度约 0 到 130 单位，起爆到消散之间，按 entityid 配对，配不上按 20 秒算）。 |
| C-HEAR 听得到 | 枪声：开枪人离用户 3D ≤ 2000；“就在旁边”：3D ≤ 600。 |
| C-FIGHT 交火第一串 | 用户上一次对着看得见的人开枪已过去 0.8 秒以上，或者上一个目标已被打死、这一枪真的对着下一个人（C-TARGET），就开始一次新交火；新交火的第一组连续开枪叫“第一串”。 |
| C-ECO 买法 | 买法取 economy.json 的 buy（eco / 强起 / 半起 / 全起）。 |
| C-GUN 枪档 | 手枪 0 < 冲锋枪和霰弹 1 < 步枪 2 < AWP/鸟狙 3。 |

## 合并层（M1–M7）

- **M1 每次阵亡只定一次责**：同一次用户阵亡命中多条规则时，按下面顺序取第一条做主因，其余写成补充从句：POST-01（问题分支）> POST-02 > POST-03 > TIME-06 > UTIL-03 > TIME-07 > TIME-08 > TIME-05 > POS-01 > POS-08 > COST-01 > POS-05 > POS-04 > POS-02 > SHOT-01/02/05 > POST-04 > TIME-03 > TEAM-04。
- **M2 技术问题照记**：开枪类（SHOT-01 到 SHOT-05）不随阵亡定责改变，照样记“你的责任”；这次死由别的规则判了合理代价时，句尾加“这次死本身算合理代价”。
- **M3 同一击杀只夸一句**：同一次击杀命中多条好的操作，主句优先级：TEAM-G1 > SHOT-G4 > SHOT-G3 > SHOT-G2 / SHOT-G1 > TEAM-G2 > UTIL-G2，其余作从句。
- **M4 好坏两面都写**：同一时刻既有好的操作又有判你责任的问题（例如 12-24.6 SHOT-05、21-22.9 SHOT-01、22-51.8 SHOT-01），两面都写；问题是“你的责任”而不是“小问题”的，好的操作不再单独成为一个时刻，只给问题句子提供事实（例如 13-47.2）。
- **M5 同一件事只出一次**：同一回合同一颗道具、同一串连杀、同一次转点，只由编号最靠前的那条规则出句子，其他规则并入从句。
- **M6 还可以**：“还可以…”只取规则 alt，引擎不自己编建议。
- **M7 句子检查**：出句前检查 P6：没有坐标、速度数字、角度、百分比；人数写成 3v2；钱数、血量、枪数、秒数可以写。

实现在 [`engine/merge.py`](../engine/merge.py)，细节和每一轮的改动见 [`docs/dev/COMPOSE_NOTES.md`](dev/COMPOSE_NOTES.md)。
